Source resolution and scan behavior

Source precedence

  1. Explicit repeated --notes-parquet paths
  2. Explicit standardized Parquet note bundle
  3. The three default PROFILE_DATA parquets

Explicit missing bundles raise immediately; they do not silently fall through to another source.

Pushdown before materialization

  • Optional MRN cohort filter
  • Optional note-type filter
  • Pipeline-specific combined trigger regex over available text columns

The lazy Polars scan limits the rows and text loaded into memory before CPU-heavy cleaning and snippet construction.

Parquet storage contract. Every repository-owned evidence, bundle, metadata, progress, failure, rejection, raw-result, label, and timeline artifact is written atomically as Zstandard-compressed Parquet. List-valued fields remain native Parquet lists. JSON is used only for provider messages or retained inside an explicit audit-value column, never as the file transport. The prostate pipelines read their default DFCI_MRN cohort from $COMPASS_PATH/mrn_lists/adt_mrns.csv; externally supplied cohort overrides are also CSV.

Shared preprocessing sequence

1LoadSelect note source, MRNs, note types, and trigger-bearing parquet rows.
2StandardizeNormalize MRNs/dates/types, map RPT_TEXT, and preserve provenance.
3Clean + scanClean each note and locate labeled regex matches in parallel processes.
4WindowExpand around matches and merge windows separated by at most 300 characters.
5PersistRank or chunk per-patient evidence and atomically write a reusable artifact.
Observable compilation. Every compilation command reports overall step progress. CPU-heavy paths also show note-level trigger scanning plus patient ranking, evidence deduplication, and chunk-packing progress.

Response handling

The shared parser accepts clean JSON, fenced JSON, the first complete JSON value, trailing-comma repair, and limited repair of unescaped quotes.

Grounding

Verbatim quotes are normalized for harmless typography and must be found in supplied evidence. Claimed source dates are checked against the supporting snippet.

Clinical context. Every system prompt is paired with a shared IRB-approved clinical-research safety preamble. No raw-note preprocessing module imports an LLM provider SDK.
Pipeline 01 · patient classifier

Binary NEPC classification

Assigns one primary prostate-cancer phenotype per cohort patient while also retaining independent AVPC, molecular AVPC, biomarker, and non-prostate-primary flags. Trigger-free patients are handled deterministically without an LLM call.

Processing steps

Prefilter notes in Parquet.

The combined trigger pattern is applied to canonical RPT_TEXT during the lazy scan. A separate MRN-only scan records which cohort members have any notes, even if none contain a trigger.

Build note candidates in parallel.

Each note is cleaned, trigger matches are labeled, nearby windows are merged, and the result records note date, type, trigger categories/count, snippet text, and raw note ID.

Rank and bound each patient payload.

Candidates sort descending by number of trigger categories, raw trigger count, and recency. The collector keeps at most 75 snippets and stops before the 300,000-character payload budget is exceeded.

Write a versioned Parquet bundle.

LLM_NEPC_classifier_patient_snippets.parquet stores version 3 metadata, one row per ordered snippet, and sentinel rows that preserve no-trigger and no-note cohort members.

Separate deterministic and LLM paths.

Triggered patients receive one LLM call. Patients with notes but no trigger are written as high-confidence conventional/no-trigger rows. Cohort patients with no notes are written as unclassified no_notes rows.

Parse and enforce cross-field invariants.

The runner validates JSON types, label precedence, AVPC criteria, C2 pattern, biomarker/molecular flags, second-primary flags, confidence, rationale, and quote/date grounding before writing a success.

Resume safely.

A run fingerprint binds the snippet SHA-256, provider, model, prompt, safety context, schema version, and output columns. Changed inputs/configuration require --overwrite. --retry-failures targets only the failure ledger.

Classification rules

Strict primary-label precedence

  1. nepc if NEPC evidence is present
  2. avpc if any canonical C1–C7 criterion is present and NEPC is absent
  3. biomarker if a qualifying somatic BRCA1/BRCA2 alteration is present and neither higher label applies
  4. conventional otherwise

Independent annotations

  • All documented somatic alterations remain in biomarker_genes.
  • Only BRCA1/BRCA2 set has_biomarker; PALB2 and other genes do not promote the label.
  • has_molecular_avpc requires at least two of PTEN, TP53, RB1.
  • Non-prostate primaries are recorded independently from the prostate phenotype.
Somatic-only rule. Germline and ambiguous germline/somatic findings do not qualify for the biomarker label or molecular-AVPC flag.

Pipeline 02 · map/reduce timeline

Longitudinal AVPC/NEPC

Builds the earliest supported onset of every canonical Aparicio AVPC criterion and independent NEPC sub-feature. Chunk-level mapping preserves atomic facts; a patient-level synthesis can complete criteria whose components appear in different notes or chunks.

Inputs and evidence contract

InputRequirement / defaultHow it is used

Clinical notesAll three note types by default; optional note-type restrictionPathology supports histology/IHC, imaging supports disease distribution, and clinical/lab context supports composite thresholds and dates.
Trigger familiesShared NEPC + AVPC plus avpc_atomicAdds Gleason, PSA, bone burden/status, LDH/CEA/calcium, ADT agents/start, and CRPC progression terms so component facts are not prefiltered away.

Processing steps

Collect and deduplicate evidence.

Trigger-bearing notes are cleaned and windowed. Identical copy-forward snippet text is deduplicated per patient, with the earliest note date retained as conservative provenance.

Assign stable patient chunk indices.

Snippets sort by note date and snippet text, then pack greedily under 60,000 characters. The collector writes DFCI_MRN, chunk_index, note_date, note_type, and snippet.

Fingerprint the evidence generation.

The sidecar records content/config hash, evidence SHA-256, schema version, context/snippet/payload settings, note types, and cohort count. A mismatch requires an intentional overwrite.

Map every outstanding chunk.

The first prompt returns complete criteria_found plus up to 30 structured evidence_items such as PSA values, lesion counts, metastatic sites, lab values/ULNs, measurements, markers, and therapy/progression dates.

Validate map findings individually.

Structural response failures reject the call; malformed individual findings are dropped while valid siblings survive. Criterion/fact-type enums, modality, confidence, quote relevance, quote grounding, source date, event date, and C2 exclusivity are checked.

Synthesize only complete patient maps.

Once every expected chunk has a successful map, a second LLM call combines facts across chunks. It may establish composite criteria but cannot relax thresholds, required conjunctions, timing, high-grade status, or exclusivity.

Validate and select one onset per criterion.

Synthesis findings receive the same grounding checks. Duplicate criteria retain the earliest supportable event, with date precision used to avoid claiming an imprecise period is certainly earlier than an overlapping precise date.

Rebuild auditable products.

Validated raw findings, rejected-finding audit, and the cumulative timeline are regenerated from durable map/synthesis logs, keeping derived products consistent with current successful state.

Canonical findings

CodeDefinition enforced by prompt/validator workflow
C1Histologic small-cell prostate carcinoma, pure or mixed.
C2Exclusively visceral metastases; concurrent bone or other non-visceral disease defeats the criterion.
C3Radiographically predominant lytic bone metastases.
C4Bulky ≥5 cm lymphadenopathy, or a ≥5 cm high-grade (Gleason ≥8) prostate/pelvic mass.
C5PSA ≤10 ng/mL in a qualifying disease context plus at least 20 bone metastases.
C6Qualifying neuroendocrine marker plus LDH/CEA ≥2× ULN or malignant hypercalcemia, without another cause.
C7CRPC/androgen-independent progression within six months of hormonal-therapy initiation.

Failure isolation and resume semantics

Partial validation success. A chunk or synthesis can be ok_with_rejections: grounded findings are preserved while invalid objects are quarantined with a reason and original JSON.
Incomplete map. Synthesis is withheld until every expected chunk has a successful map. Reruns retry only missing/failed chunks, then perform the patient synthesis when the map becomes complete.

The extraction fingerprint binds the evidence scan hash, provider, model, both full prompts, and prompt schema version longitudinal-nepc-v5.

Pipeline 03 · pan-cancer timeline

Cancer stage extraction

Extracts every explicitly documented staging event across cancer types and staging systems, resolves stated or source-note dates, and collapses repeated statements into a stage-change timeline per patient, cancer, and system.

Inputs and trigger coverage

Input scope

  • All PROFILE_DATA MRNs by default; no prostate cohort requirement.
  • Optional CSV MRN file/list and note-type restrictions.
  • Default collector context: 600 characters per side; notebook currently configures 6,000.
  • Per-snippet cap: 30,000 characters; extraction chunk budget: 60,000.

Trigger families

Stage I–IV / 1–4 TNM FIGO Ann Arbor Rai Binet Durie–Salmon Limited/extensive SCLC

Processing steps

Collect stage-bearing snippets.

The pan-cancer collector applies stage trigger regexes during the parquet scan, cleans/window notes, and deduplicates identical patient snippets while retaining the earliest note date.

Write evidence and scan metadata.

stage_evidence.parquet stores note UID, MRN, note date/type, native-list trigger categories, and snippet. The Parquet sidecar binds scan configuration and the evidence SHA-256.

Group evidence at extraction time.

The runner orders evidence chronologically and greedily packs every snippet into one or more patient chunks under payload_max_chars; no evidence row is dropped.

Extract every explicit staging event.

Each finding includes cancer type, nullable histology and primary site, a native list of metastatic sites, stated system/raw value, normalized base group, dates, historical-reference flag, quote, confidence, and rationale.

Reject invalid patient results.

Each event must have a cancer type and stage value; histology and primary site must be strings or null, and metastatic sites must be a string list. Every non-null histology/site value and the supporting quote must be grounded in the supplied note chunk; dates, stage normalization, historical status, confidence, and rationale are also validated.

Build the stage-change timeline.

Dates resolve from the stated stage date or fall back to source-note date with tracked precision. Exact duplicates collapse, while stage or metastatic-distribution changes are retained within each patient, cancer, primary-site, histology, and staging-system lineage.

Guard resumability.

The run fingerprint includes evidence SHA-256, provider, model, full prompt and safety context, schema version, output schemas, and payload size. Only patients logged ok are skipped on rerun.

No inferred stage. The model is instructed not to derive stage from “metastatic,” “localized,” treatment, response, or trajectory. TNM and non-AJCC systems are preserved as written unless the note explicitly supplies a group mapping.

Processing steps

Collect and chunk all grading evidence.

Notes are lazily prefiltered, cleaned, windowed, deduplicated per patient by snippet text, sorted deterministically, and assigned stable chunk_index values.

Verify evidence before extraction.

The runner requires a valid metadata sidecar, current evidence schema version, matching evidence SHA-256, and scan configuration consistent with any existing chunk log.

Extract each outstanding chunk.

The LLM returns primary/secondary patterns, total, explicit Grade Group, specimen type, stated scoring date, source-note date, historical-reference flag, and verbatim quote for every distinct grading event.

Validate exact integers and clinical consistency.

Primary/secondary must be integers 1–5 and appear as a pair; total must be 2–10 and equal their sum; Grade Group must be 1–5 and agree with derivation when patterns are available. A Grade Group alone remains a valid event.

Validate provenance and date direction.

Specimen type must be biopsy, prostatectomy, TURP, metastasis, or unknown. Quote/source date must ground in the current chunk, and a stated scoring date cannot follow its source note.

Persist successes independently.

Successful chunk findings are retained even if another chunk fails. The chunk log is the resume source; reruns call only outstanding chunks and preserve successful siblings.

Compact retry state and build timeline.

Append-only patient/chunk logs compact to their latest state, superseded raw retry occurrences are removed, and the timeline resolves dates, recomputes totals, derives missing Grade Groups, and deduplicates by score/group/date/specimen.

Date handling shared by timelines

Resolution order

  1. Use a valid date stated in the clinical text.
  2. Otherwise use structured source-note EVENT_DATE.
  3. Otherwise retain an unknown date/source/precision.

Partial dates

Two fixed parser anchors reveal which date components the text actually supplied. Year-only becomes January 1 with year precision; month/year becomes the first day with month precision. Results never depend on the day the pipeline runs.
