Source resolution and scan behavior

Source precedence

  1. Explicit repeated --notes-parquet paths
  2. Explicit standardized Parquet note bundle
  3. The three default PROFILE_DATA parquets

Explicit missing bundles raise immediately; they do not silently fall through to another source.

Pushdown before materialization

  • Optional MRN cohort filter
  • Optional note-type filter
  • Pipeline-specific combined trigger regex over available text columns

The lazy Polars scan limits the rows and text loaded into memory before CPU-heavy cleaning and snippet construction.

Parquet storage contract. Every repository-owned evidence, bundle, metadata, progress, failure, rejection, raw-result, label, and timeline artifact is written atomically as Zstandard-compressed Parquet. List-valued fields remain native Parquet lists. JSON is used only for provider messages or retained inside an explicit audit-value column, never as the file transport. The prostate pipelines read their default DFCI_MRN cohort from $COMPASS_PATH/mrn_lists/icd_prostate_mrn_flags.csv; externally supplied cohort overrides are also CSV.

Shared preprocessing sequence

1LoadSelect note source, MRNs, note types, and trigger-bearing parquet rows.
2StandardizeNormalize MRNs/dates/types, map RPT_TEXT, and preserve provenance.
3Clean + scanClean each note and locate labeled regex matches in parallel processes.
4WindowExpand around matches and merge windows separated by at most 300 characters.
5PersistWrite one evidence row per note, or stable patient chunks, according to the task.
Observable compilation. Every compilation command reports overall step progress. CPU-heavy paths also show note-level trigger scanning plus patient ranking, evidence deduplication, and chunk-packing progress.

Shared LLM and validation layer

Provider adapters

Both backends implement build_client() and call_with_retry(). Vertex keeps JSON completed before the output cap, then regenerates a truncated reply with more room and a higher temperature.

DFCI Azure OpenAI Google Vertex AI temperature = 0 (Gemini 3: default)

Response handling

The shared parser accepts clean JSON, fenced JSON, the first complete JSON value, trailing-comma repair, and limited repair of unescaped quotes.

Grounding

Verbatim quotes are normalized for harmless typography and must be found in supplied evidence. Claimed source dates are checked against the supporting snippet.

Clinical context. Every system prompt is paired with a shared IRB-approved clinical-research safety preamble. No raw-note preprocessing module imports an LLM provider SDK.

NEPC: four pathology-based groups

FlagDefinitionInterpretation
nepc_t1Definitive small-cell, large-cell NE, or high-grade NE carcinoma of prostatic origin; includes mixed tumors with a confirmed NE carcinoma component.Positive IHC alone is insufficient.
nepc_t2Explicitly poorly differentiated or dedifferentiated carcinoma with NE features or positive NE tissue markers, without a definitive NE carcinoma diagnosis.Intermediate/indeterminate; Gleason grade alone does not qualify.
nepc_t3Explicit prostate adenocarcinoma with focal/diffuse NE features or positive NE tissue markers.Gleason 4+5=9 with focal weak synaptophysin staining belongs here.
nepc_t4Documented prostate adenocarcinoma, completed review, and no gated NE evidence in the extracted history.Reference negative; cohort membership supplies clinical eligibility. Missing histology is not t4.

Pathology reports and explicit clinician summaries of pathology qualify. nepc_tier selects t1 > t2 > t3 > t4; t1/t2/t3 flags can reflect different historical events. Each group carries onset, precision, evidence type and quotes. The broad nepc_status includes NE evidence that does not establish a pathology group; reviewed patients with insufficient histology remain unclassified.

AVPC, AVPC-adjacent, and ARLPC

Strict AVPC

is_avpc requires metastatic disease, castration resistance, and at least one C1–C7 criterion. Small-cell histology (C1) is exempt from castration resistance but still requires metastasis. Paper numbering: C2 exclusively visceral; C3 predominantly lytic. Component findings, thresholds, and timing are checked in code.

AVPC-adjacent

No overall metastatic/CRPC state gate. Positive for extended visceral/soft-tissue metastasis (A1), any lytic bone metastasis (A2), low PSA with relaxed high-volume bone wording (A3), an explicit aggressive-variant statement (A4), or any strict C1–C7 criterion recomputed from this run. It does not read the strict AVPC output.

ARLPC annotation

Strict: reduced/negative AR IHC, AR-specific statements, or somatic genomic AR loss. Broad adds androgen-independent/hormone-refractory wording. AR-target IHC loss is corroborating only. Scans Pathology and Clinician notes; whole pathology when it fits. Independent of NE status and disease state.

Primary label precedence and unresolved inputs

ColumnNEPC entry conditionRemaining precedence
primary_labelnepc_status == "nepc" — broad, including IHC-only evidencenepc → avpc → avpc_adjacent → prad

Negative versus unresolved. A lower-precedence label requires every higher-precedence input to resolve negative. Partial review can establish a positive, never a negative. Missing/failed/unrun higher inputs leave the cascade null. The prad branch is the residual cascade label; it is not equivalent to pathology-confirmed nepc_t4.

The required tables are full-joined on DFCI_MRN; optional ARLPC is left-joined as annotation only. Duplicate MRNs, unexpected column collisions, and stale/missing label metadata raise. The merged sidecar records each input path, SHA-256, and label metadata. Gleason and met_dx_labels are not inputs to this merge.

Processing steps

Collect and chunk all grading evidence.

Notes are lazily prefiltered, cleaned, windowed, deduplicated per patient by snippet text, sorted deterministically, and assigned stable chunk_index values.

Verify evidence before extraction.

The runner requires a valid metadata sidecar, current evidence schema version, matching evidence SHA-256, and scan configuration consistent with any existing chunk log.

Extract each outstanding chunk.

The LLM returns primary/secondary patterns, total, explicit Grade Group, specimen type, stated scoring date, source-note date, historical-reference flag, and verbatim quote for every distinct grading event.

Validate exact integers and clinical consistency.

Primary/secondary must be integers 1–5 and appear as a pair; total must be 2–10 and equal their sum; Grade Group must be 1–5 and agree with derivation when patterns are available. A Grade Group alone remains a valid event.

Validate provenance and date direction.

Specimen type must be biopsy, prostatectomy, TURP, metastasis, or unknown. Quote/source date must ground in the current chunk, and a stated scoring date cannot follow its source note.

Persist successes independently.

Successful chunk findings are retained even if another chunk fails. The chunk log is the resume source; reruns call only outstanding chunks and preserve successful siblings.

Compact retry state and build timeline.

Append-only patient/chunk logs compact to their latest state, superseded raw retry occurrences are removed, and the timeline resolves dates, recomputes totals, derives missing Grade Groups, and deduplicates by score/group/date/specimen.

What counts and what is rejected

BoundaryAccepted evidenceRejected evidence
M1 vs. N1Distant bone, visceral, distant-nodal, or otherwise asserted distant metastatic diseaseRegional pelvic nodes alone, even when called metastatic adenocarcinoma
AssertionEstablished or reported-history statements; definitive imaging, pathology, and clinical assertionsNegated, hedged, suspected, benign/degenerative, and non-assertive lesion mentions

Dates and completeness

Earliest documentation

Use the stated metastasis date when available; otherwise use the earliest qualifying note date. Preserve date_source and date_precision. This is documentation timing, not an inferred biological onset. An undated positive remains positive.

Read the completion ledger

Cohort patients with no trigger-bearing evidence can receive label_source = auto_negative_no_evidence. This is not a pathology-confirmed negative. Inspect the processed-patient/chunk ledgers for failures or incomplete extraction instead of inferring completeness from a missing label.

Execution guide

Run, resume, and rebuild

Extraction and downstream rebuilding have different contracts. Keep the evidence, ledgers, and metadata alongside the final outputs.

Notebook sequence

  1. Set the provider, model, note paths, cohort and output directory. Enable RUN_COLLECT_EVIDENCE to prepare evidence.
  2. Inspect note/chunk counts, then enable RUN_EXTRACTION. Use the notebook retry toggle for incomplete work.
  3. For subtypes, run NEPC, AVPC, and AVPC-adjacent; optionally run ARLPC. Run primary_subtype.ipynb last. Its WRITE_LABELS defaults to true.
  4. Run Gleason and metastatic diagnosis independently when their outputs are needed. All extraction/collection run toggles default to false.

Version and overwrite rules

  • Unchanged collection settings reuse evidence. Changed settings require collector --overwrite, which discards downstream state.
  • Changed extraction evidence/model/prompt/schema requires a fresh extraction as directed by the fingerprint guard.
  • Subtype gate/criterion-only changes use --rebuild-labels-only, then rerun the primary merge. Newly introduced evidence types require re-extraction.
  • NEPC evidence v3 / prompt v4 adds conventional histology retrieval: migrate by recollecting and re-extracting; a label rebuild cannot recover omitted notes.
  • Metastatic diagnosis includes its veto version in the extraction fingerprint. A changed gate cannot be applied by an ordinary label-only rebuild.
